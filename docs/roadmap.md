# Roadmap / бэклог vkr-blog

Порядок — по приоритету для защиты ВКР и качества продукта. Оценки — в рабочих часах,
без учёта ревью. Перед работой сверяйся с `docs/state.md`.

## P0 — без этого защита выглядит слабо

### 1. Feature-тесты бизнес-логики (8–16 ч) — ✅ сделано

Статус: сделано. `php artisan test` → 48 тестов + 1 пропуск (поиск по кириллице
только на PostgreSQL) на sqlite `:memory:`; в контейнере — `make test`, в CI — GitHub Actions.
Покрытие — `tests/Feature/ArticleTest.php`, `CommentTest.php`, `LikeTest.php`, `SearchTest.php`.

Покрытые сценарии:
   - гость не создаёт статью → 302; автор создаёт → 201/redirect, статья в БД;
   - автор редактирует свою → ok, чужую → 403, гость → 302;
   - удаление статьи владельцем и запрет чужому;
   - лайк ставится/снимается, `likes_count` меняется;
   - комментарий создаётся, ответ привязан к родителю, `comments_count` только верхнеуровневый;
   - чужой комментарий нельзя редактировать/удалять;
   - поиск находит по кириллице в другом регистре (`ilike`);
   - slug уникален и меняется при смене заголовка;
   - XSS: `<script>` вырезается санитайзером.

Не покрыто: загрузка/удаление изображений (нет GD в тестовом образе), rate limit,
пагинация профиля.

### 2. README проекта (2–3 ч) — ✅ сделано

Сейчас в `README.md` стандартная заглушка Laravel. Нужно: что за проект, стек, скриншоты
(лента, статья, профиль, 4–5 тем), требования, установка (`composer install`, `.env`,
`migrate --seed`, `storage:link`, `npm ci`, `npm run build`), запуск, доступы демо-пользователя,
структура репозитория, описание архитектуры (маршрут → контроллер → Inertia → Vue),
реализованные требования ВКР, известные ограничения.

Готово, когда: человек с нуля поднимает проект по README без вопросов.

### 3. Решение по подтверждению почты (0–4 ч)

`MustVerifyEmail` закомментирован, `MAIL_MAILER=log`. Варианты:
- (проще, рекомендую для ВКР) оставить как есть, но явно описать в пояснительной записке
  и README: «регистрация без подтверждения, письма выводятся в лог»;
- (полноценно) включить `MustVerifyEmail`, настроить `middleware('verified')` на создание
  статьи/комментарии, в README указать MailHog/`log` для демонстрации.

Готово, когда: выбор зафиксирован в README и не противоречит тексту ВКР.

### 4. Rate limiting на контент (1 ч)

Комментарии, лайки, загрузка изображений без лимитов. Добавить `throttle` в маршруты
(например, `throttle:10,1` на комментарии, `throttle:30,1` на лайки, `throttle:20,1` на загрузку)
и тест на 429.

## P1 — заметные продукты

### 5. Аватары пользователей (4 ч)

Аксессор `User::getAvatarUrlAttribute()` есть, но `avatar` не в `fillable`, загрузки нет.
Сделать: миграция `avatar` (nullable string), валидация `image|mimes:jpg,png,webp|max:2048`,
загрузка в `profile.update`, удаление старого файла, превью в форме настроек,
отображение в `UserAvatar` (уже поддерживает), тест на загрузку/замену.

### 6. Пагинация профиля и комментариев (4–6 ч)

- Профиль: `paginate(12)` вместо `get()`, `Pagination` уже есть, сохранить статистику
  отдельным запросом. Цель — убрать ~130 КБ props у активного автора.
- Комментарии: `paginate` верхнего уровня (например, 20) с подгрузкой ответов;
  после отправки нового комментария — переход на последнюю страницу.

### 7. Черновики статей (8–12 ч)

Колонка `status` (`draft|published`) + `published_at`. Скрывать черновики из лент и поиска,
показывать автору в профиле с бейджем «Черновик», кнопки «Опубликовать/Снять с публикации».
Тесты: черновик не виден гостю, доступен владельцу.

### 8. Теги (8–12 ч)

Таблица `tags` + `article_tag`, ввод через запятую в редакторе, страница `/tags/{slug}`,
облако тегов в сайдбаре статьи. Не дублировать категории: категория одна, тегов — много.

### 9. RSS и sitemap (3–4 ч)

`/rss.xml` (последние 20 статей), `/sitemap.xml` (статьи, категории, авторы), ссылки в `<head>`.
Для блога это ожидаемая базовая вещь и плюс к SEO-разделу ВКР.

### 10. Уведомления об ответах (8–12 ч)

Ответ на комментарий/новый комментарий к статье автора: письмо (очередь `database` или `sync`)
или счётчик в навбаре. Минимум — письмо автору комментария при ответе.

## P2 — полировка, эксплуатация, a11y

### 11. Картинки: `srcset` и ресайз (6–8 ч)

Обложки и вставки: нарезка 480/960/1440 при загрузке (`intervention/image` или
`spatie/laravel-medialibrary`), `srcset`/`sizes` в карточках и статье, `width`/`height`.

### 12. Продакшн-конфиг (3–4 ч)

`nginx`: gzip/brotli, `Cache-Control: public, max-age=31536000, immutable` для `/build/*`,
`try_files`, `client_max_body_size 2m`. Плюс `.env.example` для прода, `APP_DEBUG=false`,
`php artisan config:cache route:cache view:cache` в деплой-инструкции.

### 13. Доступность (4–6 ч)

- skip-link «К основному содержимому»;
- фокус-ловушка и возврат фокуса в лайтбоксе;
- `aria-live` для flash (уже есть), проверить порядок табуляции в навбаре и меню тем;
- прогнать axe/Lighthouse и починить критичное.

### 14. Поиск: подсказки и подсветка (4–6 ч)

Debounce, подсветка совпадений в результатах, сортировка (релевантность/дата),
для больших объёмов — `tsvector` + GIN-индекс.

### 15. Страницы ошибок (2 ч)

500/403/419 в стиле сайта (404 уже есть), чтобы не показывать стандартные экраны Laravel.

### 16. Модерация (6–8 ч)

Жалобы на комментарии/статьи, скрытие по жалобам, роль модератора. Актуально, если по
требованиям ВКР есть администрирование; иначе можно не делать.

## Порядок работ (предлагаемые спринты)

1. **Спринт «Защита»**: п.1 (тесты) + п.2 (README) + п.3 (почта) + п.4 (throttle).
2. **Спринт «Профиль и контент»**: п.5 (аватары) + п.6 (пагинация) + п.15 (ошибки).
3. **Спринт «Фичи блога»**: п.7 (черновики) или п.8 (теги) + п.9 (RSS/sitemap).
4. **Спринт «Продакшн»**: п.11 + п.12 + п.13.

## Что осознанно не делаем

- Отдельный REST API — монолит на Inertia достаточен для темы.
- SSR Inertia — не требуется, сайт публичный, но не критичен к SEO настолько.
- Микросервисы/админ-панель на отдельном стеке — вне темы и сроков.
