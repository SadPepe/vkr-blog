# Управление сайтом: роли и админка

Решения по ролевой модели и минимальному набору функций администрирования.
Исходная точка: в проекте есть только «гость / авторизованный», правки контента —
исключительно владелец (`ArticlePolicy`, `CommentPolicy`), категории заводятся сидером.

## 1. Роли

Три роли + гость. Отдельная таблица ролей и пакет вроде spatie/laravel-permission
не нужны: на одну колонку меньше JOIN'ов, проще объяснить на защите.

| Роль | `users.role` | Кто | Что может |
|---|---|---|---|
| Гость | — | не вошёл | читает ленту, статьи, комментарии, поиск, страницу автора; лайк/комментарий → редирект на логин |
| Пользователь | `user` (по умолчанию) | автор блога | всё у гостя + создание/правка/удаление **своих** статей и комментариев, лайки, профиль |
| Модератор | `moderator` | помощник | всё у пользователя + скрытие любого контента, очередь жалоб |
| Администратор | `admin` | владелец сайта | всё у модератора + пользователи (роли, блокировка), категории, дашборд, удаление контента |

Правила:
- роль хранится одной колонкой `role` (string, default `user`), проверка через enum-подобный
  хелпер `User::isAdmin()` / `isModerator()` / `canModerate()`;
- модератор **скрывает** контент, админ **удаляет** — это разделение даёт смысл двум ролям
  и защищает от случайной потери данных;
- администратор не становится «автором»: чужие статьи он не переписывает, только скрывает/удаляет;
- повышение до `admin` — только через `php artisan tinker`/сидер, из интерфейса нельзя
  (админ не может создать второго админа — меньше рисков, меньше кода).

|---|---|---|---|---|

| Лайк, комментарий | ❌ | ✅ | ✅ | ✅ |
| Создать статью | ❌ | ✅ | ✅ | ✅ |
| Править/удалить **свою** статью | ❌ | ✅ | ✅ | ✅ |
| Править **чужую** статью | ❌ | ❌ | ❌ | ❌ |
| Скрыть любой пост/комментарий | ❌ | ❌ | ✅ | ✅ |
| Удалить любой пост/комментарий | ❌ | ❌ | ❌ | ✅ |
| Жалобы: рассматривать | ❌ | ❌ | ✅ | ✅ |
| Жаловаться на контент | ❌ | ✅ | ✅ | ✅ |

| Дашборд со счётчиками | ❌ | ❌ | ✅ (только контент) | ✅ |

## 3. Минимальный набор функций админки (MVP)

Пять разделов. Этого достаточно для «сайт управляется», и это реально успеть.

1. **Дашборд** (`/admin`) — счётчики: пользователи, посты, комментарии, скрытое, жалобы
   в очереди; последние 5 регистраций и 5 жалоб. Без графиков и экспорта.
2. **Посты** (`/admin/articles`) — таблица: автор, заголовок, статус, дата, просмотры;
   фильтры по статусу и поиск по заголовку; действия «Скрыть / Вернуть в публикацию»,
   «Удалить» (с подтверждением через существующий `ConfirmDialog`).
3. **Комментарии** (`/admin/comments`) — таблица: автор, фрагмент, пост, дата, статус;
   «Скрыть / Вернуть», «Удалить». Счётчик `comments_count` у поста пересчитывать
   только для видимых комментариев верхнего уровня.
4. **Пользователи** (`/admin/users`) — список с поиском по имени/email; блокировка
   (не может войти и писать), смена роли `user ↔ moderator`; число постов и комментариев.
5. **Категории** (`/admin/categories`) — CRUD: название, slug; запрет удаления, если есть посты
   (или перенос в «Без категории»); сейчас категории только из сидера, это единственный
   способ завести новую без консоли.

Жалобы (п.6) — **необязательный** раздел: включать только если в требованиях ВКР прямо
написано «модерация пользовательского контента». Кнопка «Пожаловаться» на посте/комментарии,
таблица `reports` (reporter_id, reportable_type/id, reason, status), очередь у модератора.
Без жалоб модератор работает по своей ленте — для блога этого хватает.

## 4. Выбранный путь: Filament v4, панель на /admin

Собственный интерфейс администратора не требуется — панель собирается на Filament v4
в том же приложении. Публичная часть остаётся на Inertia/Vue; общие — модели, политики, БД.
Pulse не ставим.

**Маршруты:**

| URL | Что | Кто |
|---|---|---|
| `/admin` | дашборд: счётчики + последние жалобы | модератор, админ |
| `/admin/articles` | посты: поиск, фильтр по статусу/автору, скрыть / вернуть / удалить | модератор (скрыть), админ (удалить) |
| `/admin/articles/{id}` | просмотр поста | модератор |
| `/admin/comments` | комментарии: те же действия | модератор / админ |
| `/admin/reports` | очередь жалоб: принять / отклонить / скрыть контент | модератор |
| `/admin/users` | список, поиск, роль, блокировка | админ |
| `/admin/categories` | CRUD категорий | админ |
| `/admin/login` | редирект на `route('login')` — форма входа одна | гость |
| `POST /reports` | создать жалобу (публичная часть, Inertia) | пользователь |

**Панель:** `->path('admin')`, `->authGuard('web')`,
`->authMiddleware(['auth', EnsureNotBlocked::class])`, доступ — `User::canAccessPanel()` →
`canModerate()`. Filament-логин не используем как отдельный экран: `AdminLogin extends Login`
с `redirect(route('login'))` в `mount()`. Имена маршрутов — `filament.admin.resources.*`,
проверять `php artisan route:list --path=admin`.

**БД (4 миграции):**
- `users.role` string default `'user'`;
- `users.blocked_at` timestamp nullable (разблокировка = NULL);
- `articles.status` enum(`draft`,`published`,`hidden`) default `published` +
  `articles.published_at` — **вместе с roadmap п.7 «Черновики»**, чтобы не мигрировать дважды;
- `comments.hidden_at` timestamp nullable;
- `reports`: `reporter_id`, `reportable_type/id`, `reason` enum, `comment` text nullable,
  `status` enum(`new`,`accepted`,`rejected`), `resolved_by`, `resolved_at`, индексы
  по `status` и морфам. Morph map — `article`/`comment`.

**Ресурсы и действия:** `make:filament-resource` для Article, Comment, User, Category, Report.
В Post/Comment — `Action::make('hide')->requiresConfirmation()` и `'restore'`, удаление —
`DeleteAction` только у админа. В User — поле `role` (Select) и действие `block/unblock`.
В Report — фильтр «новые», действия «принять», «отклонить», «скрыть контент» (заодно
переводит жалобу в `accepted`). Дашборд — `StatsOverview` (пользователи, посты, комментарии,
жалобы в очереди) + `TableWidget` «последние 5 жалоб».

**Политики:** Filament уважает их автоматически, поэтому `ArticlePolicy`/`CommentPolicy`
дополняются методами `hide` (модератор) и `delete` (админ); `ViewAny` — `canModerate()`.
Плюс новые `UserPolicy`, `CategoryPolicy`, `ReportPolicy`. Владелец сохраняет свои права.

**Публичная часть:** скрытые посты/комментарии — `whereNull('hidden_at')` в лентах
и 404 в `show` (кроме модератора); кнопка «Пожаловаться» в посте и комментарии (модалка
с причиной, `useForm`, `throttle:5,1`); `auth.can` в `HandleInertiaRequests` для ссылки
«Админка» в `Navbar`; `role`/`blocked_at` скрыть из публичного JSON автора.

**Деплой:** `php artisan filament:assets` (или `filament:optimize`) в сборке — прописать
в README и CI рядом с `npm run build`.

**Тесты:** гость → 302 на `/admin`; пользователь → 403; модератор скрывает чужой пост,
но не удаляет; админ удаляет и меняет роль; заблокированный не входит; скрытый пост не виден
в ленте и отдаёт 404; `comments_count` уменьшается при скрытии; жалоба создаётся и её
рассмотрение скрывает контент.

## 5. Чего осознанно не делаем

- отдельная SPA-админка и REST API — монолит на Inertia справляется;
- WYSIWYG-редактор чужих постов у админа — это редактура, а не управление;
- массовые действия (bulk), экспорт CSV, роли с правами «по галочкам» — избыточно для ВКР;
- лог действий администратора (audit log) — приятно, но не входит в минимум;
  при желании закрывается `activity_log` на 20 строк кода;
- настройки сайта в админке (title, контакты) — держим в `.env`/`config`, менять через интерфейс незачем.

## 7. Объявления от лица сайта: бегущая строка

Решение: только объявления администрации (важная информация), форма — **бегущая строка
над шапкой**. Пользовательских объявлений и отдельного раздела нет — это не меняет
природу блога.

**Как работает:** над `Navbar` тонкая полоса, текст прокручивается справа налево,
несколько активных объявлений идут подряд через разделитель. Строка закрывается крестиком,
закрытие запоминается в `localStorage` и сбрасывается, когда появляется новое объявление.

**Данные — таблица `announcements`:**
- `body` string(200) — текст одной строкой, обязателен;
- `url` nullable — необязательная ссылка на статью/страницу (текст становится ссылкой);
- `is_active` bool default `true` — ручное снятие без удаления;
- `starts_at`, `ends_at` nullable — показывать в интервале (например, только на этой неделе);
- `sort_order` int default 0 — порядок в строке; при равенстве — новые выше;
- timestamps. Скоуп `scopeActive()`: `is_active = true` и текущая дата внутри интервала.

**Админка:** Filament-ресурс `Announcement` — форма (body, url, даты, порядок),
действия «Опубликовать / Снять», фильтр «активные сейчас». Никаких картинок и HTML:
строка — это plain text, санитайзер не нужен.

**Публичная часть:**
- `HandleInertiaRequests::share()` → `announcements`: до 5 активных, `id`, `body`, `url`;
- компонент `Components/AnnouncementTicker.vue` подключается в `Layout.vue` первым элементом;
- анимация — CSS `@keyframes`, содержимое дублируется для бесшовного цикла,
  длительность считается от длины текста (`clamp`), при наведении — пауза;
- `prefers-reduced-motion` → без анимации, обычная статичная строка с переносом;
- доступность: дубликат для прокрутки с `aria-hidden="true"`, подпись «Объявления сайта»
  у контейнера, крестик с `aria-label`; `role="status"` не ставить — иначе скринридер
  будет читать строку при каждой навигации;
- токены: `bg-accent-soft text-accent`, разделитель и крестик — `text-accent/70`;
  контраст проверить во всех 14 темах, на мобиле `text-xs`, на `sm` — `text-sm`;
- полоса не липкая (навбар уже sticky), высота ~36 px, горизонтальный скролл страницы
  не появляется — только внутренний `overflow-hidden`.

**Тесты:** показываются только активные и попадающие в даты; выключенное и просроченное
не попадает в общие props; лимит 5 соблюдается.

Оценка — 3–5 ч, делать после установки Filament (этап 8). Кнопки закрытия и анимацию
фронтовыми тестами не покрываем — проверка ручная по чек-листу адаптивности.
